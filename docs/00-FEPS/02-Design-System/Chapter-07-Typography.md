# Chapter 07 — Typography

Version: 1.0.0

Status: Approved

Category: Design System

Document Owner: Finzo Team

Last Updated: July 2026

Document ID: FEPS-07

---

## Chapter Purpose

Typography is the primary communication system of the Finzo Banking Management System.

Before users interact with buttons, forms, or charts, they first read information.

A professional banking platform depends on clear, consistent, and highly readable typography.

This chapter establishes the official typography standards for the entire Finzo ecosystem.

Every page, module, component, dashboard, form, notification, report, and banking workflow must follow these typography standards.

No page may introduce its own typography style.

---

## Typography Philosophy

Typography should communicate:

Professionalism

Trust

Clarity

Hierarchy

Precision

Stability

Consistency

Accessibility

The typography system must never become decorative.

Its purpose is to help users understand financial information quickly and accurately.

---

## Enterprise Typography Principles

Every typography decision must follow these principles.

### Readability First

Text should always be easy to read.

Readable typography is more valuable than artistic typography.

---

### Consistency Before Variety

The same content type should always look the same.

A page should never contain unnecessary font variations.

---

### Hierarchy Before Size

Users should immediately understand what is important.

Hierarchy should be created through:

Size

Weight

Spacing

Alignment

Contrast

Not through excessive color changes.

---

### Simplicity Before Decoration

Avoid decorative fonts.

Avoid stylized lettering.

Avoid inconsistent capitalization.

Typography should remain clean and professional.

---

## Font Family Standards

The entire platform should use one professional typeface family.

The chosen font must provide:

Excellent readability

Multiple font weights

High-quality number rendering

Cross-platform consistency

Accessibility support

Excellent web performance

Support for future multilingual expansion

Avoid mixing unrelated font families.

---

## Font Weight Standards

Use a limited and consistent weight system.

Examples include:

Regular

Medium

Semibold

Bold

Avoid excessive use of bold text.

Bold should communicate importance—not decoration.

---

## Heading Hierarchy

Every page must follow one standardized heading structure.

Level 1

Primary page title

Used once per page.

---

Level 2

Major page sections.

---

Level 3

Subsections.

---

Level 4

Supporting groups.

---

Never skip heading levels.

Maintain semantic hierarchy for accessibility.

---

## Content Hierarchy

Information should always follow this order:

Primary Heading

↓

Supporting Description

↓

Main Content

↓

Supporting Information

↓

Actions

↓

Additional Information

This structure should remain consistent throughout the application.

---

## Dashboard Typography

Dashboards should emphasize financial information.

Priority order:

Available Balance

↓

Important Alerts

↓

Key Statistics

↓

Quick Actions

↓

Recent Activity

↓

Supporting Information

Typography should guide attention naturally.

---

## Financial Numbers

Financial values require special treatment.

Examples:

Account Balance

Transfer Amount

Interest Rate

Loan Amount

Outstanding Balance

Transaction Value

Currency

Numbers should be:

Easy to compare

Highly readable

Consistently aligned

Visually distinct from supporting text

---

## Table Typography

Tables contain critical financial information.

Table typography should prioritize:

Readability

Alignment

Scanning

Comparison

Consistency

Avoid overly condensed layouts.

---

## Form Typography

Forms should remain highly readable.

Every form should include:

Field Label

↓

Input

↓

Helper Text

↓

Validation Message

↓

Supporting Guidance

Labels should always remain visible.

Avoid relying solely on placeholders.

---

## Button Typography

Buttons should communicate actions clearly.

Button labels should:

Use concise language.

Describe the action.

Remain consistent across the application.

Examples:

Transfer Money

Download Statement

Update Profile

Approve Request

Avoid vague labels.

---

## Navigation Typography

Navigation labels should be:

Short

Recognizable

Consistent

Business-oriented

Avoid unnecessary abbreviations.

---

## Content Writing Standards

Visible content should be:

Professional

Concise

Action-oriented

Helpful

Consistent

Avoid:

Marketing hype

Buzzwords

Technical jargon

Meaningless filler

Template language

---

## Banking Terminology

The application should use professional financial terminology.

Examples:

Available Balance

Current Account

Savings Account

Beneficiary

Statement

Transaction Reference

Interest Rate

Pending Approval

Avoid inconsistent wording for identical concepts.

---

## Error Message Typography

Errors should be:

Readable

Short

Helpful

Actionable

Never display raw system messages to end users.

---

## Success Message Typography

Success messages should reassure users.

Examples:

Transfer completed successfully.

Profile updated successfully.

Password changed successfully.

Messages should remain concise and professional.

---

## Notification Typography

Notifications should:

Immediately communicate importance.

Avoid long paragraphs.

Remain easy to scan.

---

## Empty State Content

Every empty state should include:

Title

Explanation

Next Step

Optional Action Button

Never leave users without guidance.

---

## Content Density

Avoid:

Large paragraphs

Crowded interfaces

Unstructured text blocks

Use:

Headings

Lists

Spacing

Grouping

Progressive disclosure

---

## Alignment Standards

Text alignment should remain predictable.

Body content should generally use left alignment.

Center alignment should be reserved for:

Hero sections

Empty states

Confirmation screens

Success pages

Avoid unnecessary centered text within operational banking interfaces.

---

## Accessibility Standards

Typography must satisfy:

WCAG 2.2 AA

Proper heading hierarchy

Minimum readable sizing

Adequate line height

Accessible spacing

Clear contrast

Support for zoom without layout failure

---

## Localization Readiness

Typography should support future localization.

Layouts must remain flexible.

Avoid fixed-width text containers.

Support variable text lengths.

---

## Typography Consistency Rules

Every module must use the same typography system.

This includes:

Public Website

Authentication

Customer Module

Staff Module

Administrator Module

Shared Components

Reports

Settings

Support

No module may introduce custom typography patterns.

---

## Prohibited Typography Practices

Avoid:

Decorative fonts

Random font sizes

Multiple font families

Excessive bold text

Excessive uppercase

Long unstructured paragraphs

Poor spacing

Low contrast

Crowded text blocks

Typography should communicate professionalism rather than visual excitement.

---

## Typography Review Checklist

Every page must answer "Yes" to the following questions:

✓ Is the content easy to read?

✓ Is hierarchy immediately clear?

✓ Are financial values easy to identify?

✓ Are headings consistent?

✓ Are forms readable?

✓ Are tables easy to scan?

✓ Are messages concise?

✓ Is typography accessible?

✓ Is terminology consistent?

✓ Does the page communicate enterprise quality?
