# Chapter 08 — Spacing & Layout

Version: 1.0.0

Status: Approved

Category: Design System

Document Owner: Finzo Team

Last Updated: July 2026

Document ID: FEPS-08

---

## Chapter Purpose

The Layout System defines how every interface within the Finzo Banking Management System is structured.

A professional banking platform is not created by attractive components alone.

It is created by consistent structure.

This chapter establishes the official standards for:

- Layout Architecture
- Grid Systems
- Containers
- Responsive Structure
- Spacing Scale
- Content Width
- Alignment
- Dashboard Composition
- Card Placement
- Information Density
- Visual Rhythm

Every page within Finzo must follow these structural standards.

---

## Enterprise Layout Philosophy

Layout is the invisible framework that supports every interaction.

Users should never consciously notice the layout.

Instead, they should immediately understand:

Where information begins.

Where it ends.

What is important.

What belongs together.

What actions are available.

A professional layout creates confidence before users even begin reading.

---

## Core Layout Principles

Every page must satisfy the following principles.

### Structure Before Decoration

Organization is more important than visual styling.

---

### Predictability Before Creativity

Users should quickly understand page layouts without relearning each screen.

---

### Whitespace Before Borders

Use spacing to separate content.

Do not rely on excessive borders.

---

### Information Before Graphics

Financial information always receives priority over decorative visuals.

---

### Consistency Before Individual Design

Every page should feel like it belongs to the same banking product.

---

## Global Page Structure

Every page should follow one standardized structure.

Header

↓

Primary Content

↓

Supporting Content

↓

Secondary Sections

↓

Footer (Public Pages)

Operational pages may omit the footer when appropriate.

---

## Application Container Standards

Every page should use consistent content containers.

Containers establish:

Readable line lengths

Content alignment

Responsive behavior

Visual consistency

Containers should expand gracefully across screen sizes without becoming excessively wide.

---

## Responsive Grid Framework

Every layout must be built on a consistent responsive grid.

The grid should:

Maintain alignment

Prevent visual imbalance

Support flexible content

Scale naturally across devices

Never create irregular layouts.

---

## Section Composition

Every section should contain:

Section Title

↓

Optional Description

↓

Primary Content

↓

Supporting Actions

↓

Additional Information

Avoid mixing unrelated content inside one section.

---

## Content Width Standards

Different content types require different widths.

Examples:

Authentication Forms

Medium Width

Dashboard Content

Wide

Reports

Wide

Documentation

Comfortable Reading Width

Landing Page Hero

Expanded Width

Never stretch reading content unnecessarily.

---

## Dashboard Layout Standards

Enterprise dashboards should prioritize functionality.

Recommended hierarchy:

Page Header

↓

Summary Metrics

↓

Quick Actions

↓

Primary Banking Information

↓

Recent Activity

↓

Supporting Analytics

↓

Secondary Information

Never place decorative content above operational information.

---

## Card Placement Principles

Cards should follow consistent alignment.

Cards should:

Align vertically

Align horizontally

Maintain equal spacing

Share consistent heights where appropriate

Avoid irregular card placement.

---

## Section Spacing Standards

Spacing should communicate hierarchy.

Larger spacing separates major sections.

Medium spacing separates related groups.

Smaller spacing separates related elements.

Spacing should remain consistent throughout the application.

---

## Internal Component Spacing

Every component should provide adequate breathing room.

Examples:

Cards

Forms

Tables

Alerts

Charts

Statistics

Buttons

Avoid crowded interfaces.

---

## Information Density

Banking software often contains significant amounts of information.

Density should be controlled through:

Grouping

Whitespace

Hierarchy

Progressive disclosure

Never reduce readability to display additional content.

---

## Visual Rhythm

Every page should establish a predictable reading rhythm.

Users should naturally progress from one section to another without interruption.

Consistent spacing creates visual rhythm.

---

## Alignment Standards

All interface elements should align consistently.

Examples:

Page Titles

Cards

Buttons

Tables

Forms

Navigation

Charts

Icons

Statistics

Misalignment reduces perceived quality.

---

## Multi-Column Layout Standards

Multiple columns should only be used when they improve readability.

On smaller screens:

Columns should stack naturally.

Content order must remain logical.

No information should become inaccessible.

---

## Form Layout Standards

Forms should group related fields together.

Examples:

Personal Information

↓

Contact Information

↓

Security Information

↓

Preferences

Avoid long, unstructured forms.

---

## Table Layout Standards

Tables should:

Maintain consistent widths

Align numeric data properly

Provide sufficient spacing

Remain responsive

Support scrolling only when necessary

Avoid cramped table layouts.

---

## Empty Space Philosophy

Empty space is not wasted space.

Whitespace improves:

Readability

Scanning

Accessibility

Professional appearance

Do not fill space with unnecessary graphics.

---

## Hero Section Standards

Public pages may contain hero sections.

Hero sections should:

Communicate trust

Present one primary message

Include one primary action

Remain visually clean

Avoid excessive decorative content.

---

## Sidebar Layout

Sidebars should:

Remain visually lightweight

Clearly organize navigation

Support keyboard accessibility

Avoid visual clutter

Only include relevant navigation.

---

## Modal Layout Standards

Dialogs should focus on one task.

Every modal should contain:

Title

↓

Explanation

↓

Primary Content

↓

Primary Action

↓

Secondary Action

Avoid complex workflows inside modals.

---

## Responsive Layout Standards

Every page must adapt smoothly to:

Mobile

Tablet

Laptop

Desktop

Ultra-wide displays

No content should overflow.

No layout should collapse.

No interaction should become inaccessible.

---

## Layout Consistency Rules

Every module must follow the same layout principles.

Public Website

Authentication

Customer Dashboard

Staff Portal

Administrator Portal

Settings

Reports

Support

Shared Components

No module may introduce inconsistent spacing or layout patterns.

---

## Layout Anti-Patterns

Avoid:

Crowded layouts

Uneven spacing

Random alignment

Oversized containers

Tiny touch targets

Inconsistent grids

Decorative empty sections

Uneven card heights

Visual imbalance

Every layout should communicate structure and stability.

---

## Layout Review Checklist

Every page must answer "Yes" to the following questions:

✓ Is the layout balanced?

✓ Is content logically grouped?

✓ Is whitespace used effectively?

✓ Is alignment consistent?

✓ Does the page support responsive behavior?

✓ Are dashboards organized by importance?

✓ Are forms easy to complete?

✓ Are tables readable?

✓ Is information density appropriate?

✓ Does the page resemble enterprise banking software?
