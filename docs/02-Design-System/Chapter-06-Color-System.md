# Chapter 06 — Color System

Version: 1.0.0

Status: Approved

Category: Design System

Document Owner: Finzo Team

Last Updated: July 2026

Document ID: FEPS-06

---

## Chapter Purpose

The Brand Identity and Color System define how Finzo is visually recognized across the entire application.

The objective is not to create a colorful interface.

The objective is to establish a consistent, trustworthy, professional visual identity that reinforces the confidence expected from an enterprise online banking platform.

Every color, background, border, icon, illustration, status indicator, chart, and interactive element must follow the standards defined in this chapter.

No page or module may create its own color scheme.

---

## Brand Identity Philosophy

The Finzo brand should communicate:

Professionalism

Trust

Security

Reliability

Stability

Financial Confidence

Modern Banking

Enterprise Quality

The brand should feel calm rather than aggressive.

Sophisticated rather than flashy.

Professional rather than trendy.

Timeless rather than temporary.

---

## Brand Personality

Finzo should be perceived as:

Professional

Reliable

Secure

Modern

Transparent

Organized

Accessible

Efficient

Human-centered

Confident

The interface should never appear playful, experimental, or entertainment-focused.

---

## Enterprise Color Philosophy

Color is a communication tool.

Its purpose is to:

Create hierarchy

Improve readability

Communicate status

Support accessibility

Guide attention

Strengthen brand recognition

Colors should never be used simply for decoration.

---

## Primary Brand Color

The primary brand color represents trust and authority.

Recommended characteristics:

Deep Blue

Professional Navy

Financial Blue

Enterprise Blue

The primary color should be used for:

Primary buttons

Navigation highlights

Important links

Active navigation

Primary actions

Selected states

Brand accents

Avoid using the primary color excessively.

---

## Secondary Brand Color

The secondary color supports the primary brand color.

It should be used sparingly for:

Supporting actions

Charts

Secondary highlights

Supporting illustrations

Informational sections

The secondary color must never compete with the primary brand color.

---

## Accent Colors

Accent colors should draw attention only when necessary.

Examples:

Feature highlights

Interactive indicators

Progress indicators

Important statistics

Accent colors should remain limited.

---

## Neutral Color System

The majority of the interface should rely on neutral colors.

Use neutral colors for:

Backgrounds

Cards

Tables

Borders

Dividers

Input fields

Panels

Containers

Whitespace should remain the dominant visual element.

---

## Surface Hierarchy

Every interface should clearly distinguish between:

Application Background

↓

Section Background

↓

Card Surface

↓

Interactive Surface

↓

Focused Surface

↓

Active Surface

Users should immediately understand content grouping through subtle surface changes rather than excessive borders.

---

## Semantic Colors

Semantic colors communicate system status.

Every semantic color must remain consistent throughout the application.

---

### Success

Represents:

Successful transactions

Completed operations

Verified status

Approved requests

Confirmation messages

Success colors should communicate confidence without excessive brightness.

---

### Warning

Represents:

Pending operations

Review required

Temporary issues

Warnings should attract attention without creating unnecessary concern.

---

### Error

Represents:

Failed operations

Validation issues

Critical problems

Errors should be immediately recognizable while remaining readable and accessible.

Avoid alarming or overly aggressive styling.

---

### Information

Represents:

Helpful guidance

Educational content

Neutral notifications

Informational messages should remain calm and supportive.

---

## Financial Status Colors

Banking-specific statuses should remain consistent.

Examples:

Available Balance

Pending Transaction

Completed Transaction

Failed Transaction

Scheduled Transfer

Frozen Account

Locked Account

Interest Applied

Loan Active

Every financial status should use one standardized color system.

---

## Text Color Hierarchy

Text should follow a predictable hierarchy.

Primary Text

↓

Secondary Text

↓

Supporting Text

↓

Disabled Text

↓

Placeholder Text

Users should never struggle to identify important information.

---

## Background Color Standards

Backgrounds should remain subtle.

Avoid highly saturated backgrounds.

The interface should rely on spacing and hierarchy rather than background colors for organization.

---

## Border Standards

Borders should define structure rather than decoration.

Use borders to:

Separate information

Define inputs

Organize tables

Support accessibility

Avoid heavy decorative borders.

---

## Shadow Philosophy

Shadows should communicate elevation.

Not decoration.

Use minimal shadows.

Avoid:

Heavy shadows

Blur-heavy cards

Floating interfaces

Glowing elements

Large drop shadows

---

## Gradient Usage

Gradients should remain extremely limited.

Acceptable:

Brand hero sections

Illustrative marketing sections

Decorative banners (minimal)

Avoid gradients on:

Forms

Tables

Dashboards

Data-heavy interfaces

Administrative pages

Operational banking pages

---

## Dark Mode Policy

The primary experience should be designed for high-quality light mode.

Dark mode may be supported in the future but must never reduce:

Accessibility

Contrast

Readability

Brand recognition

Until officially implemented, every page should prioritize a consistent enterprise light theme.

---

## Accessibility & Color

Every color choice must satisfy WCAG 2.2 AA contrast requirements.

Never communicate meaning through color alone.

Status indicators should also include:

Labels

Icons

Supporting text

Patterns when appropriate

---

## Charts & Data Visualization

Charts should prioritize clarity over visual impact.

Use restrained colors.

Avoid rainbow palettes.

Limit the number of simultaneous accent colors.

Financial data must remain easy to interpret.

---

## Brand Consistency Rules

Every module must use the same:

Primary colors

Semantic colors

Neutral palette

Text hierarchy

Surface hierarchy

Status indicators

Charts

Buttons

Interactive states

No module may introduce its own color language.

---

## Prohibited Color Usage

The following should be avoided:

Neon colors

Oversaturated gradients

Gaming-inspired palettes

Crypto-inspired color schemes

Random accent colors

Inconsistent semantic colors

Decorative rainbow effects

Flashing color animations

Color should reinforce trust—not attract unnecessary attention.

---

## Color Review Checklist

Every page must answer "Yes" to the following questions:

✓ Does the page reinforce the Finzo brand?

✓ Are colors used consistently?

✓ Are semantic colors applied correctly?

✓ Is information hierarchy clear?

✓ Are interactive elements distinguishable?

✓ Is contrast accessible?

✓ Are financial statuses visually consistent?

✓ Does the interface feel calm and professional?

✓ Are colors supporting usability instead of decoration?

✓ Does the page resemble enterprise banking software?
