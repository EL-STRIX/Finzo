# Agent Behavioral Rules

## Version Control and Commits
- **Frequent, Atomic Commits:** Do not wait until the end of a large feature or refactor to commit. Make frequent, atomic commits in the middle of your work.
- **Commit Per Logical Change:** For example, if you fix a specific page or module, commit those changes immediately before moving on to the next page or module. The number of commits should naturally scale with the number of distinct file changes or bug fixes made during a task.
